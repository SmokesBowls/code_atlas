This is a good plan, and the scope is mostly right.

I would approve it with four corrections before implementation.

First, do not let `scanner.py` silently generate AI exports when the flags are omitted. The wording currently says omitted paths “resolve relative to `--output`,” which sounds like the exporter may always run. That would change existing behavior.

Use this rule instead:

```text
No AI export flags:
- produce only the normal report

Any AI export flag present:
- run the AI exporter

--ai-output omitted but --ai-json-output present:
- produce JSON only

--ai-json-output omitted but --ai-output present:
- produce Markdown only
```

That keeps Milestone 8 additive and avoids surprising existing users or tests.

Second, `contract_version: "1.0.0"` is too vague. It needs to name the contract it belongs to. Otherwise, later someone will see `1.0.0` and not know whether that means the scanner report, viewer, or AI packet.

Use something like:

```json
{
  "contract": "code_atlas.ai_architecture_packet",
  "contract_version": "1.0.0",
  "source_report_contract": "code_atlas.report",
  "source_report_contract_version": "..."
}
```

If the existing report does not yet expose a contract/version, record that honestly:

```json
"source_report_contract_version": null
```

Do not invent one in the exporter.

Third, the phrase “visual provenance” should be changed. This is not a visual artifact. It is semantic claim provenance.

Use:

```text
Claim provenance:
- confirmed
- inferred
- gap
```

And make sure compression never merges unlike claim types. For example, five confirmed entrypoint signals and five inferred entrypoint candidates cannot become one undifferentiated count of ten entrypoints.

Fourth, this line needs a hard boundary:

> groups similar warnings

The exporter should only group warnings when they share the same normalized reason and claim type. It must preserve the affected paths.

A safe grouped record looks like:

```json
{
  "warning_type": "single_file_static_route",
  "claim_type": "inferred",
  "count": 37,
  "affected_paths": [
    "trixelworld/engine_mr.py",
    "trixelworld/palette_mr.py"
  ]
}
```

An unsafe grouped record would be:

```json
{
  "warning": "many suspicious routes"
}
```

That loses the evidence trail.

I would send the builder this approval:

```text
Milestone 8 plan approved with required corrections.

1. AI exports must be opt-in.
   - No AI flags: preserve existing scanner behavior and produce only the normal report.
   - --ai-output alone: Markdown only.

   - Both flags: produce both.

2. Use an explicit named contract:
   contract: code_atlas.ai_architecture_packet
   contract_version: 1.0.0

   Also preserve the source report contract and version if present.
   Do not invent a source version if the normal report does not provide one.

3. Rename “visual provenance” to “claim provenance.”
   Preserve confirmed, inferred, and gap as distinct semantic classes throughout compression.

4. Warning and route deduplication must remain reversible.
   Group only records with the same normalized type and claim_type.
   Every grouped record must retain:
   - count
   - affected_paths
   - supporting evidence or source references

5. The exporter must not perform new architectural inference.
   It may normalize, sort, filter, count, deduplicate, and summarize only fields already present in the source report.

6. Output ordering must be deterministic.
   Sort paths, subsystem names, warning groups, boundaries, and equal-score inspection targets consistently.

7. Add tests proving:
   - existing scanner output is unchanged with no AI flags
   - Markdown-only and JSON-only modes work independently
   - repeated runs produce byte-identical AI JSON for the same source report
   - compression never merges different claim types
   - grouped routes retain every affected path
   - compact, standard, and full schemas are explicit and stable

Proceed with Milestone 8 only.
```

The deterministic ordering test is particularly important. “AI-friendly” is not just about fewer tokens. A stable packet lets you compare scans, cache context, and notice real architectural changes without output order shifting randomly.
